# Minute 15

- **Date:** 18/11/2026
- **Start:** 15h30
- **End:** 16h30
- **Location:** IEETA
- **Participants:**
  - **Team:** Margarida Cardoso, Artur Yavorskyy, Gil Ernesto, Nuno Costa, Tiago Costa
  - **Advisors:** Raquel Paradinha, José Gameiro

## Objective of the meeting
Present technical progress achieved across development workstreams (simplified code-to-DFD extraction, GitHub API OAuth account linking, STRIDE and LINDDUN analysis engines), demonstrate end-to-end analysis on a generated DFD, gather advisor feedback on DFD readability and UI/UX design, and assign tasks.

## Agenda
1. Demonstration of progress on the code-to-DFD generation pipeline.
2. Demonstration of GitHub API integration for connecting personal user accounts.
3. Demonstration of STRIDE and LINDDUN threat and privacy modeling engines (inputs and outputs).
4. Validation test using a DFD produced by the custom project generator.
5. Discussion of DFD visualization enhancements (element descriptions/labels) and frontend development with shadcn/ui.
6. Task division and sprint planning.

## Decisions taken

- **Progress Demonstrations:**
  - **DFD Simplification & Validation:** Demonstrated the updated code-to-DFD conversion producing a simpler, cleaner diagram aligned with project expectations. Tested the pipeline end-to-end with a DFD generated by the project's custom generator.
  - **GitHub API Integration:** Demonstrated user authentication and GitHub API integration enabling users to connect their personal accounts.
  - **Threat & Privacy Analysis Engines:**
    - **LINDDUN Engine:** Demonstrated the inputs and outputs of the privacy analysis engine and explained its detection workflow.
    - **STRIDE Engine:** Demonstrated the inputs and outputs of the threat modeling engine and its rule execution.

- **Advisor Recommendations & Feedback:**
  - **DFD Element Descriptions:** Include descriptive details and labels for arrows (data flows) and boxes/circles (processes, entities, data stores) in the DFD to provide clearer semantic context and ease interpretation.
  - **Frontend UI with shadcn/ui:** Advisors recommended leveraging [shadcn/ui](https://ui.shadcn.com/) for the frontend, noting it can simplify the presentation of information-dense sections and improve overall usability.

- **Task Assignment:**
  - **Artur Yavorskyy:** Begin the configuration and environment setup of the virtual machine (VM) provided by IEETA.
  - **Gil Ernesto:** Implement fetching private repositories using the GitHub OAuth access token.
  - **Margarida Cardoso:** Continue implementation of the LINDDUN privacy engine, including its frontend interface.
  - **Tiago Costa:** Continue implementation of the STRIDE threat engine, including its frontend interface.
  - **Nuno Costa:** Continue refining and improving the automated DFD generation pipeline.
